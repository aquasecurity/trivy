Audit Category Definitions & Scope Discipline (9.1.2 Scoped)
P0 — Customer-Facing Grammar & Formatting
Misspellings, grammatical errors, typos, product name/branding changes, or visual formatting inconsistencies (e.g., duplicated words, unclosed quotes, irregular spacing before colons, uncapitalized acronyms, broken pluralization) in literal error strings and flag usage texts shown across UI and CLI outputs. Internal code identifiers, log-only debug strings, and comments are strictly excluded.
P0 — Non-Actionable "Contact Support" Errors
Errors notifying the user of a failure using a generic escalation instruction ("Contact Support", "Contact Administrator", "GSS", "Global Support", or bare "Support") without explaining the root cause of the failure or providing an actionable self-service resolution step. (0 findings detected in this component).
Other Observations Outside Scope (Non-P0 / Informational)
  • Notice: Several internal helper errors in build scripts (e.g., support/gobuild/helpers/target.py) use developer-facing exceptions like "Product owner failed to implement...". These are build-system scripts and not shipped runtime CLI errors.
  • Notice: Deprecated CLI flags (such as --security-checks, --reset-policy-bundle, and client subcommand) contain deprecation warnings directing users to modern equivalents. These are intentional backwards-compatibility shims.
  • Notice: In support/release-machinery-ci/ci.go, error returns from GitHub PR status comments are intentionally discarded with _ = relmci.PostToGithub(...) to prevent secondary CI reporting failures from failing the overall build pipeline.
